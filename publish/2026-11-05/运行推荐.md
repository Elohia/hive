# 运行推荐 · HIVE 0.1.0（2026-11-05）

> 结论先行：**先 doctor，再 scan，再单任务 run，最后才 daemon。**
> 不要一上来就常驻 —— 先看它扫出来的是不是你真关心的事，再决定让它一直跑。

## 一、五分钟上手（照抄能跑）

```powershell
cd D:\hive

# 1) 环境自检：不跑模型、不发请求，只看通道
node --no-warnings scripts/hive.mjs doctor

# 2) 跑一轮感知（邮箱 / git / 文档 / 本机自动化 / 自检）
node --no-warnings scripts/hive.mjs scan

# 3) 看待办，判断噪声大不大
node --no-warnings scripts/hive.mjs inbox

# 4) 投一个"只读"任务，看它自己判几级、派给谁
node --no-warnings scripts/hive.mjs run "总结 D:\hive\docs 下现在有什么，列 3 条待办" --drain

# 5) 满意了再常驻
node --no-warnings scripts/hive.mjs daemon
# 打开 http://127.0.0.1:8787
```

开机自启（可选）：`scripts/install-task.ps1`（注册计划任务）。备份/恢复：`scripts/backup` / `scripts/restore`。

## 二、配置怎么调（config/hive.json）

| 项 | 建议值 | 理由 |
|:--|:--|:--|
| `server.host` | 保持 `127.0.0.1` | 默认无 token；绑 0.0.0.0 等于把控制台开给整网 |
| `server.token` | 留空 = 仅本机；要远程必须设 | 看板能"派单执行"，等于能驱动你的 Agent |
| `dailyBudgetCny` | 先设 8，跑一周再动 | 实测单次上下文归纳 ¥0.011，正常一天几毛；超了系统自己暂停派单 |
| `executors.codex.enabled` | 先 `false` | 本机实测上游余额不足会 402；充值或改 `~/.codex/config.toml` 的 provider 再开 |
| `executors.proc` | 不用就删/关 | 没配 `command` 会一直报"不可用"，自检那 1 条 WARN 就是它 |
| `executors.dsh` | 保持开 | 实测最稳的执行器（v0.1.5-rc.2，跑通带文件证据的报告），冷启动约 55s |
| `priority.quietThreshold` | 先看两天 Inbox 再调 | 调高 = 更安静，但可能漏掉你想要的"小机会" |

## 三、执行器怎么选（实测口径）

| 执行器 | 适合 | 实测 |
|:--|:--|:--|
| `llm`（内联） | L1/L2 判定、摘要、上下文归纳 | 24h 2 次，成功 100%，均 6.5s，花费 ¥0.03 |
| `dsh` | 要读写文件、要证据的活（L3/L4 默认走它） | 24h 10 次，成功 90%，均 58.7s |
| `pi` | 备选进程执行器 | 已装 1.5.0，可用，未派活 |
| `codex` | 等余额/配置修好再开 | 可用但会 402 |
| `claude` | 备选 | 可用（2.1.195），未派活 |
| `shell` | 本地脚本类 | 24h 3 次，全失败 —— 说明它接到的都是需要模型判断的活，别用 shell 兜底 |
| `proc` | 未配置 | 不可用（正常） |

一句话：**判定用便宜的 llm，干活动用 dsh，别让 shell 接需要判断的任务。**

## 四、安全与边界（别跳）

1. **不可逆/对外/花钱的动作只走"待拍板"**。这是设计不变量，不要为了省事加 `--no-approval` 到常驻流程里。
2. **看板不对外**。8787 只绑本机、token 留空；要远程先设 token，再考虑反代。
3. **预算必须有上限**。`dailyBudgetCny` + 单任务 token/时长上限，是唯一能兜住"模型跑飞"的东西。
4. **失败要看，不要只重试**。失败进 events/runs 和看板；连续失败先查通道（代理 7890、凭据、CLI 版本），别指望重试能治。
5. **先只读跑三天**。让它只扫、只判定、只出报告，确认它扫出来的东西你认，再放开 L4/L5。

## 五、第一小时清单

- [ ] `doctor` 全绿（或只剩 proc 那条 WARN）
- [ ] `scan` 能在 30 秒内出结果，Inbox 条数在你能看完的量级（>50 条说明阈值太低）
- [ ] 投一条只读任务，确认它判的等级你认可（该 L1 的没被派给进程执行器）
- [ ] 看板能开、SSE 实时刷新
- [ ] `dailyBudgetCny` 设好，当日花费显示正常
- [ ] 决定要不要开机自启

## 六、常见问题

| 现象 | 原因 | 处理 |
|:--|:--|:--|
| 看板打不开 | daemon 没起 / 端口占用 | `hive serve` 单独起；查 8787 占用 |
| 执行器大面积失败 | 上游 402 / CLI 不在 PATH / 代理不通 | 先 `doctor`，看"外部通道"那几行 |
| 花费飙升 | 任务被反复重试 / 强模型被默认使用 | 看 events 里的 retry；把判定模型固定成 cheap |
| Inbox 噪声大 | 订阅/退信/低价值源没降权 | 调 `quietThreshold`、关掉不关心的 sensor |
| 任务卡在"运行中" | 进程没退出 / 租约过期 | 看门狗会回收；查 `data/runs/<id>/` 的 stdout/stderr |
